# ADR-001: Модульний моноліт

- **Статус:** Прийнято (2026-11-26, фіксує рішення, яке діє з Дня 3)
- **Контекст дня:** День 7, тиждень 1
- **Пов'язано:** `docs/architecture.md` (розділи 2–3), ADR-004, `tests/Architecture/ModuleBoundariesTest.php`

## Контекст

Dwellio робить одна людина за 4–6 тижнів. У продукті чотири чітко різні зони: квартири (CRUD), пошук (hybrid search), генерація оголошень (стрімінг) і AI-шар (провайдери, облік токенів). Навантаження портфоліо-рівня, але дизайн має пояснювати, що буде при 100×.

## Порівняння

| Критерій | Модульний моноліт | Мікросервіси | «Звичайний» Laravel (`app/Models`, `app/Http`) |
|---|---|---|---|
| Деплой і CI | Один образ, один пайплайн | N образів, N пайплайнів, контракти між сервісами | Один образ |
| Межі модулів | Явні, перевіряються Pest Architecture tests | Фізичні (мережа) | Немає: будь-що імпортує будь-що |
| Транзакції | Звичайні транзакції PostgreSQL | Saga / outbox | Звичайні |
| Операційна ціна (RAM на 1 ГБ EC2) | Мінімальна | Неприйнятна для `t3.micro` | Мінімальна |
| Незалежне масштабування | Процесами: php-fpm, Reverb і воркери — окремі контейнери з одного образу | Повне | Так само процесами, але без меж у коді |
| Шлях до виділення сервісу | Модуль уже має контракт → винести за HTTP/черги | — | Спершу рефакторинг |

## Рішення

`app/Modules/{Listings,Search,Generation,AI}` + `app/Shared`. Кожен модуль: `Actions/`, `DTO/`, `Http/`, `Models/`, `Jobs/` за потреби. Правила залежностей:

```text
Listings  ← базовий модуль, ні від кого не залежить
Search    → Listings, AI\Contracts         (не знає про Generation)
Generation→ Listings, AI\Contracts         (не знає про Search)
AI        → нічого з доменних модулів; єдиний, хто імпортує laravel/ai
Shared    → не залежить від модулів
```

Ці правила — не домовленість, а тести (`tests/Architecture/*`): порушив межу → червоний CI. Масштабуємо **процеси**, а не сервіси: той самий образ запускається як `php-fpm`, `reverb`, `worker-embeddings`, `worker-generation`.

## Наслідки

**Плюси**
- Один деплой, одна БД, звичайні транзакції; уся інфраструктура вміщається в `t3.micro` + swap.
- Межі видно в структурі папок і гарантовано тестами — на співбесіді це «виконувана документація».
- Виділити модуль у сервіс дешево: контракти (`EmbeddingClient`, `TextStreamClient`, `TokenBudget`) уже є точками розрізу.

**Мінуси і ризики**
- Спільна БД: модулі можуть «прорости» один в одного через SQL (Search читає таблиці Listings напряму). Пом'якшення: читання лише, запис — тільки через Actions власника.
- Один релізний цикл: баг у Generation блокує деплой Search.
- Architecture tests ловлять лише `use`-залежності, не SQL і не події.

## Альтернативи, що відхилені

- **Мікросервіси.** Мережеві виклики, розподілені транзакції, N пайплайнів і N контейнерів на 1 ГБ RAM — ціна без вигоди для однієї людини й одного продукту.
- **Стандартна структура Laravel.** Швидший старт, але межі зникають за тиждень, а історія «що винести при 100×» стає розмитою.

## Умови перегляду

- Окрема команда на модуль або різні цикли релізів.
- Generation потребує іншої мови/рантайму (наприклад, Python для власної моделі).
- Профіль навантаження модулів розходиться настільки, що спільна БД стає вузьким місцем (див. ADR-003).
